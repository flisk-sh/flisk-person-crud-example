# Flisk person CRUD example

A small people directory (create, list, edit, delete) built from five services and started with one command:

```bash
flisk up people
```

| Service | What it is | How Flisk runs it |
| --- | --- | --- |
| `person-app` | React + Vite UI | Flisk `frontend` resource |
| `person-api` | Express API on Bun: CRUD in MongoDB, list cached in Redis, an event per change on RabbitMQ | Flisk `backend` resource |
| `person-events` | Worker that consumes the RabbitMQ queue and logs each event | Flisk `worker` resource |
| `mongo` | MongoDB 7 on port 4600 | `bring-your-own` image, no Traefik route |
| `redis` | Redis 7 on port 4610 | `bring-your-own` image, no Traefik route |
| `rabbitmq` | RabbitMQ 3.13 (AMQP) on port 4620 | `bring-your-own` image, no Traefik route |

You edit each service's `service.json` and source. Flisk writes the Dockerfiles, Compose file, Tilt config and Traefik routes under `.autogenerated/` and `.flisk/`. No Kubernetes is needed on the laptop.

## Run it


> **Repository-pinned CLI (optional):** Run `bun install` from the repository root to install the version pinned in `package.json`. Use `bun run flisk:project` to initialize project config, `bun run flisk:dry-run` to preview startup, or `bun run flisk:up -- <stack>` to start a stack. The global npm and standalone binary installation paths remain available.

Needs Docker, [Tilt](https://docs.tilt.dev/install.html) and the [Flisk CLI](https://github.com/flisk-sh/flisk#quick-start).

```bash
bun install
flisk up people
```

The first start builds the base images and can take several minutes.

- UI: http://localhost:8080/person-app/
- API: http://api.flisk-person-crud-example.localhost:8080/api/person/persons
- Tilt dashboard: http://localhost:10350

## Try the API

```bash
API=http://api.flisk-person-crud-example.localhost:8080/api/person

curl -s -X POST $API/persons -H 'Content-Type: application/json' \
  -d '{"name":"Ada Lovelace","email":"ada@example.com","age":36}'

curl -si $API/persons | grep -i x-cache   # MISS, then HIT within 30 s
curl -s $API/health/ready                 # mongo, redis and rabbitmq status
```

Each create, update and delete shows up in the worker's log in the Tilt dashboard (`person-events`), for example `[Worker] person.created Ada Lovelace <ada@example.com>`.

## How the data services are wired

Flisk has no built-in MongoDB, Redis or RabbitMQ container, so each one is a `bring-your-own` resource with a two-line Dockerfile in `services/people/<name>/`. Flisk's bring-your-own ports are 4000-5999, so each Dockerfile moves the service onto its `service.json` port, and `"exposeViaProxy": false` keeps them off Traefik. The API and worker reach them on the Docker network by name: `mongo:4600`, `redis:4610`, `rabbitmq:4620`.

RabbitMQ's built-in `guest` user only accepts local connections, so the Dockerfile creates a `people`/`people` user. That is a local-development credential only.

Data lives inside the containers and is lost when they are removed.

## Layout

```
services/people/
  person-app/      React UI (src/App.tsx)
  person-api/      Express API (src/index.ts)
  person-events/   RabbitMQ consumer (src/index.ts)
  mongo/ redis/ rabbitmq/   bring-your-own Dockerfiles
```
